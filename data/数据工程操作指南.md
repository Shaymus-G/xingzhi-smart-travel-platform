## 三、高德地图API准备

### 3.1 注册高德开放平台

1. 访问 https://lbs.amap.com/
2. 注册账号并登录
3. 进入"应用管理" → "我的应用" → "创建新应用"
4. 应用类型选择"其他"
5. 添加 Key，服务平台选择"Web服务"
6. 获取到 API Key

### 3.2 当前使用的API及配额说明

本项目使用高德地图 **Web服务API**，具体接口：

| 接口 | 用途 | 每日配额（个人开发者） |
|------|------|----------------------|
| 行政区域查询 | 获取城市列表 | 约 5000 次 |
| POI搜索（文本） | 获取景点/酒店/餐饮数据 | 约 5000 次 |

> **注意**：系统配置为爬取全国所有城市，但每个城市每种POI只取1页（约25条，实际可用10-20条）。
> 总请求量估算：约300个城市 × 3种POI类型 × 1页 = 900次请求，在个人开发者配额（约5000次/日）范围内。

### 3.3 API Key 配置

在 `config.py` 中配置：

```python
# 高德地图API Key
AMAP_API_KEY = "你的API_KEY"
```

## 四、爬虫系统说明

### 4.1 文件结构

```
data_engineering/
├── __init__.py           # 模块初始化
├── config.py             # 全局配置（API Key、目标城市、请求间隔等）
├── models.py             # SQLAlchemy ORM 模型（与数据库表对应）
├── amap_client.py        # 高德地图API客户端（封装请求、重试、限流）
├── city_crawler.py       # 城市数据爬取模块
├── poi_crawler.py        # POI数据爬取模块（景点/酒店/餐饮）
├── data_cleaner.py       # 数据清洗与转换（API字段→Schema字段映射）
├── db_manager.py         # 数据库管理（连接、建表、插入数据）
├── main.py               # 主入口（编排整个爬取流程）
└── 数据工程操作指南.md    # 本文件
```

### 4.2 各模块职责

#### config.py - 配置文件

- 高德地图 API Key
- **爬取策略**：默认 `USE_ALL_CITIES = True` 爬取全国所有城市
- 每个城市每种POI类型只取1页（约10-20条数据）
- 请求间隔时间（避免触发限流）
- 每页大小、最大页数等参数

#### amap_client.py - API客户端

- 封装 HTTP 请求
- 自动重试机制（网络错误、限流时重试）
- 请求频率控制（每个请求之间间隔一定时间）
- 统一的错误处理和日志记录

#### city_crawler.py - 城市数据爬取

- 调用高德地图行政区域查询接口
- 获取省份 → 城市列表
- 提取城市名称、省份、经纬度
- 写入到 cities 表对应的 CSV 或直接入库

#### poi_crawler.py - POI数据爬取

- 按城市、按类型爬取 POI 数据
- 支持的 POI 类型：
  - `景点` → scenic_spots 表
  - `酒店` → hotels 表
  - `餐饮服务` → restaurants 表
- 分页获取（每页最多25条）

#### data_cleaner.py - 数据清洗

将高德API返回的字段映射到数据库Schema字段：

| 高德API字段 | 对应表 | 目标字段 | 处理方式 |
|------------|--------|---------|---------|
| name | 三张表通用 | name | 直接使用 |
| location | 三张表通用 | latitude, longitude | 拆分逗号分隔的字符串 |
| address | scenic_spots/hotels | address | 直接使用 |
| type | scenic_spots | category | 提取一级分类 |
| type | restaurants | type | 提取一级分类 |
| rating | scenic_spots/hotels/restaurants | score | 字符串转浮点数 |
| cost | hotels/restaurants | price/price_level | 字符串转浮点数 |
| business_area | scenic_spots | - | 可补充到address |
| photos[0].url | 三张表通用 | image_url | 取第一张图片 |
| adname | 三张表通用 | - | 用于校验city_id |
| website | scenic_spots | - | 可选补充 |

#### db_manager.py - 数据库管理

- 建立数据库连接（支持 SQLite 和 MySQL）
- 自动创建表结构
- 批量插入数据
- 数据去重（避免重复插入）

#### main.py - 主入口

- 编排完整的爬取流程
- 命令行参数支持（指定城市、类型等）
- 进度显示

## 五、分步操作说明

### 第1步：配置API Key和爬取策略

打开 `config.py`，确认以下配置：

```python
# 填入你的高德地图API Key
AMAP_API_KEY = "你的API_KEY"

# 爬取全国所有城市（默认True）
# 每个城市每种POI类型只取1页（约10-20条数据）
USE_ALL_CITIES = True

# 如果想只爬取部分城市，将 USE_ALL_CITIES 设为 False
# 并在 TARGET_CITIES 中指定城市名
# USE_ALL_CITIES = False
# TARGET_CITIES = ["北京", "上海", "成都"]
```

> **配额估算**：全国约300个城市 × 3种POI类型 = 900次请求，在个人开发者日配额（约5000次）范围内，可以放心运行。

### 第2步：测试API连接

运行以下命令测试API是否正常：

```bash
# 激活环境
source venv/bin/activate

# 测试城市列表获取
cd data_engineering
python -c "from amap_client import AMapClient; client = AMapClient(); print(client.get_city_list()[:3])"
```

如果返回城市数据，说明API Key有效。

### 第3步：爬取城市数据

```bash
python main.py --step cities
```

这将：
1. 调用高德地图行政区域查询接口
2. 获取全国所有省份和城市列表（约300个城市）
3. 将结果保存为 CSV 并自动入库

### 第4步：爬取POI数据

```bash
# 爬取所有类型的POI数据（景点/酒店/餐饮）
python main.py --step pois

# 或只爬取指定类型
python main.py --step pois --poi-types 景点 酒店
```

这将：
1. 遍历全国所有城市（约300个）
2. 对每个城市，按类型爬取POI数据（每类只取1页，约25条）
3. 原始数据保存为 CSV 备份
4. 预计总请求量：300城市 × 3类型 = 900次

### 第5步：数据清洗与入库

```bash
python main.py --step clean
```

```bash
python main.py --step load
```

这将：
1. 读取原始CSV数据
2. 按 `data_cleaner.py` 的映射规则清洗数据
3. 将清洗后的数据插入数据库

### 第6步：一键执行全部流程

```bash
python main.py --step all
```

这将依次执行：城市爬取 → POI爬取 → 数据清洗 → 数据入库

### 第7步：数据验证

```bash
python main.py --step verify
```

验证数据库中的数据：
- 各表是否有数据
- 数据完整性检查
- 统计信息输出

### 第8步：从 SQLite 迁移到 MySQL（可选）

当需要部署上线时，只需一步即可将 SQLite 中的所有数据迁移到 MySQL：

```bash
# 前提：MySQL 已安装并创建好数据库（见第六节）
# 迁移数据（使用 config.py 中配置的 MySQL 连接信息）
python main.py --step migrate

# 或指定 MySQL 连接参数
python main.py --step migrate \
  --mysql-host localhost \
  --mysql-port 3306 \
  --mysql-user xingzhi_user \
  --mysql-password 你的密码 \
  --mysql-database xingzhi
```

迁移流程：
1. 自动从 SQLite 读取所有数据
2. 连接 MySQL 并创建表结构
3. 自动处理城市ID映射关系（SQLite和MySQL的自增ID可能不同）
4. 批量写入所有 POI 数据
5. 输出迁移后的数据统计

## 六、数据库搭建

### 6.1 选择数据库模式

系统支持两种模式：

**模式A：SQLite（开发测试用）**

- 无需安装数据库服务
- 数据存储在本地文件
- 适合开发和测试阶段

配置方式：
```python
# config.py 中设置
DB_TYPE = "sqlite"
DB_PATH = "data/xingzhi.db"  # 数据库文件路径
```

**模式B：MySQL（生产环境用）**

- 需要安装 MySQL 服务
- 支持并发访问
- 适合正式部署

MySQL 安装与配置流程：

```bash
# 1. 安装 MySQL（Ubuntu/Debian）
sudo apt update
sudo apt install mysql-server -y

# 2. 启动 MySQL 服务
sudo systemctl start mysql
sudo systemctl enable mysql

# 3. 初始化安全配置
sudo mysql_secure_installation
# 按提示设置 root 密码，其他选项可根据需要选择

# 4. 登录 MySQL 创建数据库
sudo mysql -u root -p
```

进入 MySQL 后执行：

```sql
-- 创建数据库
CREATE DATABASE xingzhi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 创建专用用户（可选）
CREATE USER 'xingzhi_user'@'localhost' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON xingzhi.* TO 'xingzhi_user'@'localhost';
FLUSH PRIVILEGES;

-- 退出
EXIT;
```

```bash
# 5. 安装 pymysql（Python连接MySQL的驱动）
pip install pymysql
```

配置方式：
```python
# config.py 中设置
DB_TYPE = "mysql"
DB_HOST = "localhost"
DB_PORT = 3306
DB_USER = "xingzhi_user"      # 或 root
DB_PASSWORD = "你的密码"
DB_NAME = "xingzhi"
```

## 七、常见问题

### Q1: API返回"INVALID_USER_KEY"

**原因**：API Key 无效或未配置 Web服务权限
**解决**：检查 Key 是否正确，确认服务平台选择了"Web服务"

### Q2: 请求被限流（返回错误码 10003）

**原因**：请求频率过高
**解决**：增加 `config.py` 中的 `REQUEST_INTERVAL` 值

### Q3: 某城市POI数据为空

**原因**：该城市可能没有该类型的POI数据，或城市名称不匹配
**解决**：检查城市名称是否正确，可尝试使用 adcode 代替城市名

### Q4: 数据量太大，配额不够

**建议**：
1. 只爬取重点城市（5-10个）
2. 每个城市只爬取核心区域的POI
3. 分批爬取，分多次完成
