13. 五类 Tab 方案
────────────────────────────────────────────────────────────────────────────────
  决策：Tab 值直接使用 resource_type（统一语义）

  type CityResourceTab =
    | 'scenic_spot'
    | 'hotel'
    | 'restaurant'
    | 'entertainment'
    | 'shopping_mall'

  Tab 展示：
    景点 | 酒店 | 餐厅 | 娱乐 | 商场

  横向滚动（scroll-view scroll-x），避免小屏拥挤。
  纯文本 Tab，无图标依赖。
  默认选中 'scenic_spot'。
  不显示每类数量（减少 API 预请求）。


14. 懒加载方案
────────────────────────────────────────────────────────────────────────────────
  决策：方案 B — 首次只加载默认 Tab（景点），切换时首次懒加载。

  每类数据状态：
    interface TabState<T> {
      items: T[]
      loading: boolean
      loaded: boolean
      error: string | null
    }

  五类状态:
    const scenicState    = reactive<TabState<ScenicSpot>>({ items:[], loading:false, loaded:false, error:null })
    const hotelState     = reactive<TabState<Hotel>>({ ... })
    const restaurantState = reactive<TabState<Restaurant>>({ ... })
    const entertainmentState = reactive<TabState<Entertainment>>({ ... })
    const mallState      = reactive<TabState<ShoppingMall>>({ ... })

  懒加载函数:
    async function ensureTabLoaded(tab: CityResourceTab): Promise<void> {
      const state = getState(tab)
      if (state.loaded || state.loading) return
      state.loading = true; state.error = null
      try {
        state.items = await LOADERS[tab](cityId)
        state.loaded = true
      } catch (err) { state.error = message }
      finally { state.loading = false }
    }

  LOADERS 映射:
    scenic_spot:     () => getScenics({city_id})
    hotel:           () => getHotels({city_id})
    restaurant:      () => getRestaurants({city_id})
    entertainment:   () => getEntertainments({city_id})
    shopping_mall:   () => getMalls({city_id})

  理由：
    - 一次请求最少（只加载用户正在看的 Tab）
    - 每类错误独立处理
    - 首次加载速度快（只请求 1 类，不是 5 类）


15. Tab 缓存方案
────────────────────────────────────────────────────────────────────────────────
  缓存规则：
    1. loaded=true 后不再重复请求（包括空数组）
    2. 切回已加载 Tab 直接展示
    3. 请求失败时 loaded=false → 可以重试
    4. 重试期间保留旧数据（或为空）
    5. 城市 ID 改变时清空全部状态（onLoad 重新初始化）
    6. 不使用持久化缓存
    7. 不使用 Pinia Store

  不需要主动刷新入口（用户可以通过切回再切出的方式重新触发）。后续可增加下拉刷新，但不是 Task-4 必需。


16. 是否需要分页
────────────────────────────────────────────────────────────────────────────────
  决策：方案 A — 不实现分页。每类一次加载 limit=50。

  理由：
    - 娱乐数据约 180 条/36 城市 → 每城市约 5 条
    - 商场数据约 180 条/36 城市 → 每城市约 5 条
    - 酒店/餐厅每城市数据量也有限（limit=50 足够覆盖任一城市）
    - 当前城市详情从未有过分页交互
    - 引入 5 套独立分页状态会大幅扩大 Task-4 范围

  保持 limit=50（与酒店/餐厅当前实际首次加载一致）。
