## 一、项目概述

### 1.1 项目背景

当前旅游信息获取存在三大痛点：信息分散在多个平台（地图、攻略、餐饮、天气需切换 3--4 个 App）、个性化推荐不足（依赖热门排行，忽略个人偏好）、旅行规划成本高（制作攻略平均耗时 3--5 小时）。

"行知"旨在利用大语言模型（LLM）、多源旅游数据和个性化推荐算法，构建一个从目的地选择、路线规划到出行服务的一站式智慧文旅平台。

### 1.2 核心定位

> **"行知" = 旅游数据 + AI 对话 + 行程生成 + 社交互动**

区别于传统旅游 App 的被动搜索模式，"行知"围绕 AI 驱动旅游决策：

```
用户提出需求 → AI 理解意图 → 结合真实旅游数据 → 生成个性化方案
```

### 1.3 技术架构总览

```
┌────────────────────────────────────────────────┐
│     移动端 App（uni-app + Vue3 + HBuilderX）    │
├────────────────────────────────────────────────┤
│      后端服务层（FastAPI + SQLAlchemy 2.0）     │
├────────────────────────────────────────────────┤
│     数据层（TiDB Cloud 云数据库 + 天气 API）     │
├────────────────────────────────────────────────┤
│      AI 智能层（DeepSeek v4 + 推荐引擎）        │
└────────────────────────────────────────────────┘
```

## 四、技术实现亮点

### 4.1 后端架构

#### 三层分层设计

```
┌──────────────────────────────────────────┐
│   API 层（7 个 Router 模块）              │
│   请求校验 · 认证鉴权 · 响应格式化 · CORS  │
├──────────────────────────────────────────┤
│   Service 层（6 个 Service 模块）         │
│   CRUD · 密码哈希 · AI 编排 · 推荐 · 天气  │
├──────────────────────────────────────────┤
│   Data 层（ORM + 数据库）                 │
│   SQLAlchemy 2.0 · Alembic · TiDB Cloud  │
└──────────────────────────────────────────┘
```

#### 技术选型

- **FastAPI**：异步 Web 框架，自动生成 Swagger 文档，性能优于 Flask
- **SQLAlchemy 2.0**：Mapped + mapped_column 声明式 ORM，类型安全
- **Alembic**：数据库版本管理，Git 式迁移工作流
- **JWT + bcrypt**：无状态认证，适配移动端
- **Pydantic v2**：请求/响应自动校验，from_attributes 支持 ORM 序列化

#### API 接口统计

| 模块 | 端点数 | 典型接口 |
|------|--------|----------|
| 用户 /api/users | 8 | register、login、me、preferences |
| 旅游资源 /api/travel | 20 | cities/scenics/hotels/restaurants/plans CRUD |
| 社交 /api/social | 7 | favorites（含去重）、reviews（含 mine） |
| AI /api/ai | 3 | chat（DeepSeek 实时）、sessions |
| 天气 /api/weather | 2 | current、forecast |
| 推荐 /api/recommend | 4 | nearby、similar、contrast、collaborative |
| **合计** | **44** | |

#### 安全防护

- 速率限制：普通接口 200次/分钟，AI 接口 20次/分钟，超限返回 429
- 请求体限制 1MB，安全响应头（X-Content-Type-Options、X-Frame-Options）
- JWT 认证所有写接口，收藏/评论含用户所有权校验
- AI 异常不泄露内部堆栈，统一返回 503 + 用户可读描述
- CORS 生产环境限定 Render 域名，开发环境本地全开

### 4.2 AI 智能模块

- 接入 DeepSeek v4-Flash 大模型，通过 OpenAI 兼容 SDK 调用
- 多轮对话上下文管理：读取最近 20 条历史消息，最大 8000 字符合并
- 独立封装为 `xingzhi_ai` 可复用包（client + context + prompts + exceptions）
- 系统提示词将 AI 定位为"行知文旅助手"，引导模型给出结构化建议

### 4.3 个性化推荐引擎

四种推荐策略协同工作：

| 策略 | 算法 | 示例 |
|------|------|------|
| 周边城市 | Haversine 球面距离 | 杭州→绍兴(42km)、嘉兴(73km) |
| 相似城市 | 区域 + 等级 + Jaccard 类别相似度 | 杭州→青岛、烟台（同为华东热门沿海） |
| 反差城市 | 区域 + 等级 + 类别差异最大化 | 杭州→哈尔滨、喀什（南北跨越、新鲜体验） |
| 协同过滤 | 用户偏好余弦相似度 | "相似用户也收藏了" |

### 4.4 前端实现

- 技术栈：uni-app（HBuilderX）+ Vue3 + TypeScript
- 页面体系：首页、城市详情、景点详情、AI 对话、登录/注册、个人中心、收藏、编辑资料、设置（共 13 个页面）
- 组件库：CityCard、ScenicCard、NavBar、SafeImage、ReviewItem、Loading、EmptyState
- 请求层：自动注入 JWT Token、统一解析 `{code, message, data}`、401/403 跳转登录
- CORS 跨域修复：前端提出并协同后端添加 CORSMiddleware 解决跨域问题

## 八、项目总结

### 8.1 核心创新点

1. **AI 驱动旅游决策**：不是简单搜索，而是理解用户需求并生成个性化方案
2. **多源数据融合**：融合地图 POI、用户评论、天气信息构建统一旅游知识库
3. **个性化推荐**：基于地理位置 + 特征相似度 + 用户偏好的混合推荐策略
4. **一站式平台**：从发现目的地到 AI 规划行程，无需切换多个 App
