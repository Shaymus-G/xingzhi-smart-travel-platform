## 二、娱乐场所 & 商场 API

### 接口

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/api/travel/entertainments?city_id=257` | 否 | 娱乐场所列表 |
| GET | `/api/travel/entertainments/{id}` | 否 | 娱乐场所详情 |
| GET | `/api/travel/malls?city_id=257` | 否 | 商场列表 |
| GET | `/api/travel/malls/{id}` | 否 | 商场详情 |

### 响应格式

与景点/酒店/餐厅完全一致：

```json
{
  "code": 0,
  "data": [
    {
      "id": 1, "city_id": 257,
      "name": "XX KTV",
      "category": "KTV",
      "score": 4.2, "price": 200.0,
      "address": "杭州市西湖区...",
      "open_time": "10:00-02:00",
      "latitude": 30.2417, "longitude": 120.1452,
      "image_url": "https://picsum.photos/...",
      "description": null
    }
  ]
}
```

### 数据字段说明

| 字段 | 说明 | 娱乐场所示例值 | 商场示例值 |
|------|------|--------------|-----------|
| category | 细分类别 | KTV / 电影院 / 酒吧 / 网吧 | 购物中心 / 百货 / 商业街 |
| score | 评分 0-5 | 4.2 | 4.5 |
| price | 参考价格（元） | 200 | null |
| open_time | 营业时间 | "10:00-02:00" | "10:00-22:00" |

### 支持分类筛选

前端可基于 `category` 字段做 Tab 切换：

```
娱乐场所分类：KTV | 电影院 | 酒吧 | 网吧 | 洗浴 | 游戏厅
商场分类：购物中心 | 百货 | 商业街 | 奥特莱斯
```

## 三、交通路径规划 API

### 接口

| 方法 | 路径 | 认证 | 说明 |
|------|------|------|------|
| GET | `/api/transit/route` | 否 | 任意两点间路径规划 |
| GET | `/api/transit/between-spots` | 否 | 景点间快捷接口 |

### GET /api/transit/route

**参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| from_type | string | 是 | 起点类型：scenic_spot / hotel / restaurant / entertainment / shopping_mall |
| from_id | int | 是 | 起点资源 ID |
| to_type | string | 是 | 终点类型（同上） |
| to_id | int | 是 | 终点资源 ID |
| method | string | 是 | 出行方式：transit / driving / walking / bicycling |
| city | string | 否 | 城市名（公交模式必填，如"杭州"） |

**响应示例（公交）**：

    "steps": [

### 四种出行方式对比

| method | 返回信息 | 适用场景 |
|--------|---------|---------|
| transit | 公交/地铁线路号、上下车站名、换乘站、经停站数、票价 | AI 旅行计划推荐公共交通 |
| driving | 路线指引、距离、时长、红绿灯数、高速费 | 自驾游规划 |
| walking | 步行路线、距离、时长 | 短距离相邻景点 |
| bicycling | 骑行路线、距离、时长 | 共享单车出行 |

### GET /api/transit/between-spots

快捷接口，只需传两个景点 ID，自动获取城市名：

```
GET /api/transit/between-spots?spot_a_id=6324&spot_b_id=6325&method=transit
```

## 五、AI 旅行计划增强

### 路径规划集成建议

AI 旅行计划的 `plan_json.itinerary.items` 中，相邻景点的 `transport_to_next` 字段目前只是文字描述（"步行前往""打车约 15 分钟"）。AI 组可以调用 `/api/transit/between-spots` 获取真实路径数据填入：

```python
# AI 组在生成行程后，为相邻景点补充交通信息
import httpx

resp = await httpx.get(
    "https://xingzhi-smart-travel-platform.onrender.com/api/transit/between-spots",
    params={"spot_a_id": 6324, "spot_b_id": 6325, "method": "transit"}
)
transit_info = resp.json()["data"]
# transit_info 包含详细公交/地铁线路号、换乘站、票价
```

### 候选资源扩展

旅行计划生成时，`ai_plan_service.py` 的 `generate_travel_plan()` 目前查询的候选资源包括景点、酒店、餐厅。如需将娱乐场所和商场也纳入 AI 计划生成的候选数据中，联系国峻赫更新 `ai_plan_service.py`。

## 六、各同学需要做什么

### 前端

| 任务 | 具体操作 |
|------|---------|
| 城市详情页加"娱乐""购物"两个 Tab | 调用 `GET /api/travel/entertainments?city_id=` 和 `GET /api/travel/malls?city_id=` |

## 九、注意事项

1. 交通 API 依赖高德地图 Key，已在 Render 和本地配置，前端无需额外操作
2. 娱乐/商场数据仅覆盖 36 个重点城市，其他城市查出来是空列表（返回 `[]`，不会 500）
3. 公交模式 `method=transit` 时**必须传 city 参数**（`/api/transit/between-spots` 会自动获取）
4. 新数据已含 Picsum 图片，无需再跑图片回填脚本
5. 所有新接口无需登录，与现有接口风格完全一致
