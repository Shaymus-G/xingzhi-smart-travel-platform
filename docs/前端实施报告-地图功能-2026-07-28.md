## 3. 实现说明

### 3.1 类型增加了哪些字段

**PlanTimelineItem（新增 6 个可选字段）：**
```typescript
latitude: number | null
longitude: number | null
city: string | null
district: string | null
poi_id: string | null
coordinate_system: string | null
```

**PlanMeal / PlanHotel（各新增 3 个）：**
```typescript
latitude: number | null
longitude: number | null
city: string | null
```

**PlanDestination（新增 2 个）：**
```typescript
latitude: number | null
longitude: number | null
```

### 3.2 Normalizer 如何兼容历史数据

- 字段别名兼容：`raw.latitude ?? raw.lat`、`raw.longitude ?? raw.lng ?? raw.lon`
- 坐标验证：string→number 转换 + isFinite + 范围检查（纬度 -90~90，经度 -180~180）
- 无效值 → `null`（不转为 0，不伪造）
- 空字符串 → `null`
- 历史数据缺失 → `null`（默认值）
- normalizer 不因坐标异常导致整个计划解析失败

### 3.3 坐标验证规则

```
normalizeCoordinate(value, min, max):
  null/undefined → null
  number: isFinite + min≤v≤max → v | null
  string: trim + Number() + isFinite + min≤v≤max → number | null
  其他类型 → null
```

**经纬度顺序保护：**
- 内部存储：`{ latitude, longitude }`（语义顺序：纬度在前）
- 高德 URI 参数：`position=lng,lat`（高德顺序：经度在前）
- `buildAmapViewUrl/buildAmapNavigationUrl` 中显式写死 `${loc.longitude},${loc.latitude}`

### 3.4 资源详情延迟查询流程

```
用户点击 🗺️ 地图按钮
  → handleOpenMap(item, dayIndex, itemIndex)
    → 节点有坐标？→ 直接 showMapActionSheet()
    → 节点有 resource_type + resource_id？
      → nodeKey 加入 mapLoadingKeys（按钮显示"查询中..."）
      → fetchResourceCoordinates(type, id)
        → 缓存命中？返回缓存
        → 缓存未命中？调用对应 getXxxDetail(id)
        → 结果存入页面级 Map 缓存
      → 查询成功？→ normalizeLocation(detail.lat, detail.lng) → showMapActionSheet()
      → 查询失败？→ 继续降级
    → 无坐标无资源 ID？→ 直接 showMapActionSheet(null)
  → showMapActionSheet():
    → 有坐标：['查看地点', '从当前位置前往']
    → 无坐标：['在高德地图中搜索']
    → uni.showActionSheet → tapIndex → openMapUrl()
```

### 3.5 缓存策略

- 页面级 `Map<string, ResourceDetailResult>` 缓存
- Key：`resource_type:resource_id`（如 `scenic_spot:6324`）
- 跨节点共享（同一资源多个 node 使用相同缓存）
- 并发请求防重：`Map<string, Promise>` 去重
- 页面卸载时 `clearResourceCache()` 清理

### 3.6 高德 URL 构造

| 函数 | 用途 | URI 格式 |
|------|------|---------|
| `buildAmapViewUrl(loc, keyword)` | 查看地点 | 有坐标：`/marker?position=lng,lat&name=...` 无坐标：`/search?keyword=...` |
| `buildAmapNavigationUrl(loc, keyword)` | 导航 | `/navigation?to=lng,lat,名称&mode=car` (仅坐标有效时) |
| `buildAmapWebUrl(loc, keyword)` | H5 Web 版 | 同上但无 `callnative=1` |

全部 URL 附带 `src=行知`。

### 3.7 App/H5 打开策略

```text
App (app-plus):
  plus.runtime.openURL(appUrl, failCb)
    → 失败：plus.runtime.openURL(webUrl, failCb2)
      → 失败：uni.setClipboardData(webUrl) → toast

H5:
  window.open(appUrl, '_blank')
    → 返回 null（弹窗阻止）：window.location.href = webUrl
```

不做小程序 Map 适配（本轮范围外）。

### 3.8 地图按钮交互

- 位置：地址行右侧（`.tl-address-row` flex 布局）
- 文案：🗺️ 地图 / 查询中...
- 样式：小号蓝色边框按钮，不抢占主体空间
- 事件：`@tap.stop` 阻止冒泡（不影响行程节点点击跳转详情）
- 禁用：加载中时不可重复点击
- 不影响 TransitRoutePanel 位置和功能

## 7. 人工验收步骤

### 7.1 H5 端

1. 启动 H5 开发服务器：`cd frontend && npm run dev:h5`
2. 打开一个已有旅行计划详情页（如 `#/pages/plan/detail?id=1`）
3. 检查每个行程节点的地址行右侧是否有 🗺️ 地图按钮
4. 点击"🗺️ 地图"按钮：
   - 应有 ActionSheet 弹出
   - 选择"查看地点"→ 应打开新窗口/跳转高德 Web 页
5. 如果节点无坐标：
   - ActionSheet 应显示"在高德地图中搜索"
   - 点击后应跳转高德搜索页

### 7.2 Android App 端

1. HBuilderX 连接真机，运行到 Android
2. 同样进入计划详情页
3. 点击地图按钮：
   - 已安装高德：应唤起高德 App
   - 未安装高德：应降级到 Web URL
   - Web 也失败：应弹出"已复制地图链接"提示
4. 检查按钮在未登录、loading 等状态下的表现
5. 检查 TransitRoutePanel 的路线查询功能未受影响
