# 前端联调所需后端支持

目前前端准备继续处理线上图片显示问题。“个人中心 → 我的评论”模块暂缓开发，但现有后端接口无法支持该页面，现整理以下后端需求。

## 一、“我的评论”接口需求

当前已有接口：

```http
GET /api/social/reviews
```

该接口必须传入：

```text
target_type
target_id
```

只能获取某一个景点、酒店或餐厅的评论，无法获取当前登录用户发表的全部评论。

请新增：

```http
GET /api/social/reviews/mine?skip=0&limit=20
Authorization: Bearer <JWT>
```

### 1. 查询规则

接口应当：

* 根据 Bearer Token 识别当前用户；
* 只返回当前用户自己发表的评论；
* 按 `created_at` 倒序排列；
* 支持 `skip` 和 `limit` 分页；
* 不允许通过查询参数指定其他用户；
* 同时返回被评论目标的名称和图片。

### 2. 建议响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [
      {
        "id": 1,
        "target_type": "scenic_spot",
        "target_id": 5,
        "target_name": "西湖风景名胜区",
        "target_image": "https://example.com/image.jpg",
        "content": "景色很好。",
        "score": 4.5,
        "created_at": "2026-07-21T10:00:00+08:00",
        "updated_at": "2026-07-21T10:00:00+08:00"
      }
    ],
    "total": 1,
    "skip": 0,
    "limit": 20
  }
}
```

### 3. 字段约束

`target_type` 建议只允许：

```text
scenic_spot
hotel
restaurant
```

`score` 应统一返回数字，不要在不同接口中混用数字和字符串。

`target_name` 和 `target_image` 应根据 `target_type` 联查对应的：

```text
scenic_spots
hotels
restaurants
```

目标资源被删除时，也不应导致整个接口返回 500。可以返回：

```json
{
  "target_name": "目标已删除",
  "target_image": null
}
```

### 4. 编辑与删除权限

现有接口：

```http
PUT /api/social/reviews/{review_id}
DELETE /api/social/reviews/{review_id}
```

需要确认：

* 只能编辑自己的评论；
* 只能删除自己的评论；
* 修改或删除其他用户评论时返回 403 或 404；
* 评论不存在时返回 404；
* 参数错误返回 422；
* 未登录返回 401；
* 不要将数据库异常直接暴露给前端。

### 5. 路由与测试

建议将该接口放在实际负责 `/api/social` 路由的模块中，不建议放入推荐系统模块。

请补充测试：

* 未登录访问；
* 正常分页；
* 用户之间的数据隔离；
* 目标类型分别为景点、酒店和餐厅；
* 目标资源已删除；
* 编辑他人评论；
* 删除他人评论；
* 空评论列表；
* 分页边界。

## 二、线上图片字段需求

当前使用的线上后端地址是：

```text
https://xingzhi-smart-travel-platform.onrender.com
```

前端在连接该地址时存在图片无法显示的问题。请检查以下接口返回的图片字段：

```http
GET /api/travel/cities
GET /api/travel/cities/{city_id}
GET /api/travel/scenics
GET /api/travel/scenics/{scenic_id}
GET /api/travel/hotels
GET /api/travel/restaurants
GET /api/social/favorites
```

重点字段包括：

```text
cover_image
image_url
avatar
target_image
```

### 1. 图片 URL 基本要求

后端返回的图片地址必须满足：

* 浏览器和 Android 真机均可访问；
* 线上环境不得返回 `localhost`；
* 线上环境不得返回 `127.0.0.1`；
* 不得返回 Windows 本地路径；
* 不得返回服务器文件系统绝对路径；
* HTTPS 页面优先返回 HTTPS 图片；
* 图片不存在时返回 `null`，不要返回无效占位字符串；
* 同一种资源统一使用同一个图片字段名。

不应返回：

```text
http://127.0.0.1:8000/uploads/a.jpg
E:\project\xingzhi\data\a.jpg
./static/a.jpg
undefined
None
```

### 2. 相对路径约定

推荐直接返回完整 HTTPS URL，例如：

```text
https://xingzhi-smart-travel-platform.onrender.com/static/images/a.jpg
```

如必须返回相对路径，请统一使用：

```text
/static/images/a.jpg
```

不要同时混用：

```text
static/a.jpg
/static/a.jpg
uploads/a.jpg
http://localhost:8000/uploads/a.jpg
```

### 3. 静态资源服务

如果图片由 FastAPI 提供，请确认：

* 静态目录已经正确挂载；
* 部署包中实际包含对应文件；
* URL 路径和文件路径一致；
* 图片请求返回 200；
* `Content-Type` 为正确的 `image/*`；
* 文件名大小写与 Linux 部署环境一致；
* 不依赖开发电脑上的本地目录。

如果图片需要长期上传和持久保存，建议使用稳定的对象存储或图床，并在数据库中保存公网 URL。

### 4. 联调信息

请后端提供至少以下样例：

```text
1 个城市图片 URL
1 个景点图片 URL
1 个酒店图片 URL
1 个餐厅图片 URL
```

并说明：

* 图片是外部图床还是后端静态文件；
* 相对路径应以哪个后端地址拼接；
* 图片不存在时返回什么值；
* 线上数据库中的图片字段是否包含 localhost；
* Render 部署中是否包含静态图片目录。

---

## 三、验收条件

后端完成后，请确保：

1. `GET /api/social/reviews/mine` 可以在 Swagger 中测试；
2. OpenAPI 中包含明确的请求参数、Bearer 鉴权和响应模型；
3. 当前用户评论能够正确分页；
4. 编辑、删除操作有用户所有权校验；
5. 线上接口不再返回 localhost 图片地址；
6. 提供的图片 URL 可直接在浏览器新标签页打开；
7. 图片不存在时不会导致接口 500；
8. 所有接口错误响应保留正确的 CORS 响应头。
