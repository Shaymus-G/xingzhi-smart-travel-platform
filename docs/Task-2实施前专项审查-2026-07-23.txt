4. 当前列表状态和缺口
────────────────────────────────────────────────────────────────────────────────
  当前状态机（仅 2 个状态）：
    loading → plans (ready/empty)
    error → 伪 empty（catch 为空，plans=[]）

  需要补充的状态机：
    loadingInitial  → 首次加载，显示 loading spinner
    ready           → 数据正常，列表渲染
    empty           → 数据为空且非错误，显示空引导
    refreshing      → 下拉刷新中，保留旧数据
    loadingMore     → 触底加载更多，列表底部显示加载指示器
    errorInitial    → 首次加载失败，显示错误+重试按钮
    errorLoadMore   → 加载更多失败，Toast提示
    deleting        → 删除中，对应项显示 loading 或禁用
    noMore          → 已加载全部，底部显示"没有更多"

  缺失的状态变量：
    - refreshing: boolean
    - loadingMore: boolean
    - hasMore: boolean
    - error: string | null（区分网络错误和空列表）
    - page/skip: number


5. 后端列表契约
────────────────────────────────────────────────────────────────────────────────
  来源：backend/app/api/travel.py:235-244

  GET /api/travel/plans
    JWT: 是（get_current_user）
    skip: Query(0, ge=0)
    limit: Query(20, ge=1, le=100)
    排序: created_at DESC (travel_service.py:243)
    过滤: user_id == current_user.id
    返回: { code:0, data: TravelPlanResponse[] }
          → request() 自动解包为 TravelPlan[]

  关键事实：
    - 默认 limit=20（不是 50，当前前端传入 50 但仍被后端限制在 ≤100）
    - 后端不返回 total
    - 后端不返回 has_more
    - 空数组 = 该用户无计划或已到末尾
    - 删除后 skip 偏移：若删除第一页中间一项，下次加载更多时会漏掉被挤出的一项
    - 新增计划后按 created_at DESC 排序，新计划出现在第一页顶部

  结论：使用 skip/limit 追加分页。
        从返回数组长度 < limit 判断 hasMore。


6. 推荐分页方案
────────────────────────────────────────────────────────────────────────────────

  决策：方案 A — skip/limit 追加

  实现：
    const PAGE_SIZE = 20
    let currentSkip = 0

    首次: getMyPlans({ skip: 0, limit: PAGE_SIZE })
    加载更多: getMyPlans({ skip: plans.value.length, limit: PAGE_SIZE })

    hasMore 判断: returned.length === PAGE_SIZE → 可能还有更多
                  returned.length < PAGE_SIZE → 没有更多

  理由：
    - 后端无 total 字段 → 方案 B (页码) 无法判断 lastPage
    - skip=当前列表长度 天然避免重复（删除后可能漏一项，但概率低且可接受）
    - 实现简单，不需要维护页码状态

  不需要处理删除后补拉（过度设计）。

  刷新时：
    currentSkip = 0
    plans.value = []（或新数据直接替换）

  跨端兼容：
    - H5: enablePullDownRefresh → 浏览器原生下拉
    - 微信小程序: enablePullDownRefresh → 小程序下拉
    - Android App: enablePullDownRefresh → 原生下拉

  此变更同时解决"加载更多"的触发方式：onReachBottom 替代 @scrolltolower。


8. 请求锁、竞态与去重
────────────────────────────────────────────────────────────────────────────────

  风险场景：
    1. 刷新未完成时触底 → 互斥锁阻止
    2. 加载更多未完成时再次触底 → 互斥锁阻止
    3. 删除期间刷新 → 等待删除完成后刷新
    4. 多次 onShow 同时触发请求 → 互斥锁 + 旧请求结果丢弃

  推荐：boolean lock 方案（最小实现）

  状态变量：
    const isBusy = ref(false)  // 正在执行任何列表操作

  规则：
    - loadingInitial: isBusy=true
    - refreshing: isBusy=true
    - loadingMore: isBusy=true
    - 以上三者互斥，同一时间只有一个为 true
    - onShow 时如果 isBusy=true，跳过刷新

  不做：
    - request token（AbortController）
    - 全局请求队列
    - 结果版本号

  理由：当前页面规模不需要复杂方案。布尔锁足够覆盖最常见竞态场景。


9. DELETE 接口契约
────────────────────────────────────────────────────────────────────────────────
  来源：backend/app/api/travel.py:277-285

  DELETE /api/travel/plans/{plan_id}
    JWT: 是
    权限: plan.user_id == current_user.id
    成功: success(message="计划已删除") → { code:0, message:"...", data:null }
    不存在: HTTPException(404, "计划不存在")
    无权限: 同上（404，不暴露存在性）
    重复删除: 404（计划已不存在）

  request() 对 DELETE 的处理：
    - statusCode 200 → code===0 → resolve(data) → data 为 null/undefined
    - 但 request() 的 http.delete() 定义为：
      delete<T>(url, params?) → request<T>(url, { method:'DELETE', data:params })
    - 对于 deletePlan，T 应为 void，resolve 返回 undefined（可接受）

  推荐前端签名：
    export function deletePlan(id: number): Promise<void> {
      return http.delete<void>(`/api/travel/plans/${id}`)
    }

    模板区分：

18. API 错误处理分工
────────────────────────────────────────────────────────────────────────────────

  当前 request() 行为：
    - 自动解包 data（code===0 → resolve data）
    - 401 → 全局跳转登录
    - 422 → 解析 detail 数组
    - 网络错误 → 友好中文 message
    - 其他错误 → reject Error(message)

  Task-2 应遵守的分工：
    request 层：Token 注入、全局 401、网络错误转换
    页面层：特定业务的 Toast、重试逻辑、UI 状态

  规则：
    - DELETE 成功: request 返回 void → 页面移除该项 + Toast "已删除"
    - DELETE 404: request reject → 页面 catch + Toast "计划不存在" + 刷新列表
    - GET 列表失败: 页面设置 error 状态 + 显示重试按钮（不 Toast）
    - 加载更多失败: 页面 Toast 提示 + 保留旧数据

  避免：
    - request 层和页面层各弹一次 Toast
    - 加载更多失败把整个列表换成错误页
